# Акко — что сделано и как с этим работать

Краткая передача дел. Подробности для пользователей — в [README.md](README.md).

## Что это

Маленький чернильный робот Акко, который бегает по экрану: ~50 трюков (джетпак, шарик, по стене, колесо, мячик…).
Глаза следят за курсором, его можно схватить и бросить. Изначально был React-компонентом для сайта
(`HopBot.tsx` / `HopBot.css` в корне — **оригинал, не трогали**). Теперь это:

1. **Библиотека** `core/` — без зависимостей, для любого сайта или приложения.
2. **Приложение для macOS** `mac/` — нативное (Swift + системный WebKit). **Готово, установлено, работает.**
3. **Приложение для Windows** `desktop/` — Electron. **Код написан, но не собирался и не запускался.**

## Структура

```
core/            библиотека akko (TypeScript → dist/ через esbuild)
  src/engine.ts    поведение: выбор трюков, ходьба, прыжки, бросок (перенос из HopBot.tsx без React)
  src/index.ts     публичный API createAkko(), пауза/скрытие, режим чернил
  src/art.ts       рисунок: каждая подвижная часть — HTML-блок со своим маленьким SVG; 3 копии для «кипения»
  src/lines.ts     jitter(): копия рисунка с чуть сдвинутыми точками (для «кипящих» чернил)
  src/chelik.css   все стили и позы (сгенерированы из HopBot.css, классы chelik-*/rb-*)
  src/react.ts     обёртка <Akko />
  demo.html        демо-страница
mac/             приложение macOS
  Sources/main.swift            окно-оверлей, строка меню, хоткей, сон/батарея, настройки (UserDefaults)
  Sources/SettingsWindow.swift  окно настроек (SwiftUI)
  Sources/AutoHide.swift        прятаться при видео / полноэкранном режиме
  Sources/World.swift           «мир»: окна (спереди назад), Dock, иконки рабочего стола → в страницу при изменениях
  Sources/FrameCap.swift        потолок кадров для анимаций (60, при экономии 30) — разгружает WindowServer
  web/overlay.html, bridge.js   страница внутри WebKit, мост JS ↔ Swift
  build.sh                      сборка .app (arm64+x86_64) и .dmg в mac/build/
desktop/         Electron-версия (для Windows): main.js, preload.js, overlay.*
scripts/         icons.py (иконки: только голова, без антенны), sync-core.mjs (копирует библиотеку в desktop/)
```

## Команды

```bash
cd core && npm install && npm run build          # библиотека → core/dist
python3 -m http.server -d core 5178              # демо: http://localhost:5178/demo.html
cd mac && ./build.sh --run                       # собрать и запустить мак-приложение
ditto "mac/build/Akko.app" "/Applications/Akko.app"   # установить
cd desktop && npm install && npm start           # Electron (Electron уже скачан в node_modules)
cd desktop && npm run dist:win                   # установщик Windows (не проверено)
```

## Как устроено мак-приложение

- Прозрачная панель на весь экран ниже строки меню, поверх окон, не забирает фокус. Ходит он по самому низу экрана
  (в том числе перед доком); Dock — просто предмет, на который он иногда запрыгивает (трюк `dock`, флаг `upDock`).
- **Мир вокруг** (`World.swift`, настройка «Лазить по окнам и доку», `climb`): раз в секунду (2 с при экономии)
  приложение спрашивает у WindowServer рамки окон (`CGWindowListCopyWindowInfo`, ~0.35 мс, разрешений не надо)
  и отдаёт в страницу `desk.world({b:[[id, вид, x, y, w, h]…]})` — только если что-то поменялось. Вид: 0 окно,
  1 иконка, 2 Dock. Пока он стоит на окне (JS шлёт `perch`), опрос 10 раз/с, чтобы ехать вместе с окном.
  Ширину Dock без разрешений прикидываем по его настройкам (число плиток × размер); с «Универсальным доступом»
  берём точную рамку (AX: список у процесса Dock) и иконки рабочего стола (AX: картинки в области прокрутки Finder).
  AX-запросы идут в фоне раз в 6 с — медленный Finder не тормозит приложение.
- **Глаза** (`Sight.swift`, нужна «Запись экрана», кнопка в настройках «Мир»): Акко сам узнаёт формы, без
  подогнанных чисел. Для каждого нового окна снимает верхнюю полоску этого окна (ScreenCaptureKit, только оно,
  без тени) и ищет первую сплошную строку — видимый верх — и столбец — бок; в World рамка окна ужимается до
  видимой. Раз в 20 с снимает окно Dock (видна только его панель → её рамка; панели нет — док спрятан) и окно
  рабочего стола Finder (там только иконки → пятна нужного размера = иконки). Читается только прозрачность,
  в памяти. Без разрешения — прикидки (ширина дока по настройкам, иконки через «Универсальный доступ»).
  Лог: `chelik sight: …`. Разрешение (как и «Универсальный доступ») сбрасывается при каждой новой ad-hoc сборке.
- **Опора под ногами** (`below()` в движке): падая (спрыгнул, бросили, окно уехало из-под ног), он приземляется
  на ближайшую поверхность ниже — видимую крышу окна, иконку, Dock или пол. Прыгая с окна вперёд, не может
  приземлиться на него же или на окна за ним. Оказавшись на крыше, продолжает там (трюк `perched`).
- В движке (`engine.ts`, раздел «On the desktop»): трюки `climb` (на окно: по боковой стороне, большим прыжком или
  на джетпаке), `icons` (по иконкам), `dock`. Наверху: гуляет, сидит, свешивает ноги, прячется за окном, которое
  лежит поверх, и выглядывает; окно потащили — едет (`ride`), закрыли/свернули — падает. «За окном» — это
  `clip-path` на корне Акко: видимая часть экрана, нарезанная полосами по краям передних окон; ставится один раз
  на изменение, не каждый кадр (замер: ходьба с обрезкой стоит столько же, ~5%).
- Пока он на Dock, выбираются только трюки из `ON_DOCK`; трюк для пола, заказанный из меню, — сначала спрыгнет.
  Брошенный мышью сверху на док — приземлится на него.
- Окно настроек компактное: шапка (статус, трюк, пауза, показать) и вкладки «Акко / Мир / Система».
  Хук `CHELIK_SNAP` заодно сохраняет картинку окна настроек (`settings.png`), `CHELIK_TAB=n` — открыть вкладку.
- Клики проходят насквозь. Swift спит, пока мышь не двинется (глобальный монитор движений, разрешений не нужно),
  потом 0.4 с следит за курсором 30 раз/с; плюс проверка раз в 0.5 с на всякий случай. JS сообщает, когда курсор
  над Акко (`onInteractive`), и тогда панель начинает ловить мышь.
- Управление: значок-голова в строке меню, окно настроек (открывается при повторном запуске приложения
  или при самом первом запуске), хоткей ⌘⌥⇧M.
- Прячется сам: пока какое-то приложение держит экран включённым (`IOPMCopyAssertionsByProcess`: так делают
  видео и звонки) и когда активное приложение на весь экран. Возвращается после 6 с «тишины».
- Пауза / спрятан / блокировка / сон → движок остановлен, CSS-анимации на паузе, ~0% CPU.
- Экономия энергии «Авто» = на батарее или в Low Power Mode: 30 кадров и без «кипения» чернил.
- Настройки: `defaults read dev.minichelik.mac`. Пока приложение запущено, правьте их только через само приложение:
  при выходе оно перезапишет значения, записанные через `defaults write`.

## Производительность — важные находки (не сломать!)

Цифры — в % одного ядра на MacBook Pro M3 Pro (сумма трёх процессов: приложение + WebKit WebContent + WebKit GPU),
курсор не двигался. «Было» — версия до оптимизации 17.11.2026.

| Режим | Было | Стало | Память (3 процесса) |
|---|---|---|---|
| пауза / спрятан | ~0% | ~0% | ~42 МБ |
| стоит (дышит, моргает, чернила) | 14% | 2.5% | ~45 МБ |
| ходит / бегает | 27% | 5% | ~52 МБ |
| обычная жизнь (все трюки подряд) | 27% | 7% | ~52 МБ (было до 160) |
| то же, экономия энергии | 19% | 4% | ~50 МБ |

Плюс системный WindowServer: пока что-то анимируется, он перерисовывает экран. На 120 Гц это было ~+19% ядра,
с потолком 60 кадров ~+12%, на 30 кадрах (экономия) ~+7%.

Главное правило WebKit: **всё, что двигается, должно быть анимацией, которую играет видеокарта, а не скрипт.**
Любое изменение страницы из JS (класс, стиль, атрибут, новый элемент) стоит ~4 мс перерисовки, сколько бы ни менялось.
Поэтому важно число таких изменений в секунду, а не их размер.

1. **Каждая подвижная часть — отдельный HTML-блок** (`.rb-p`) со своим маленьким SVG поверх общей сетки 72×104
   (`--q` — одна клетка сетки, в ней же заданы сдвиги в keyframes). Анимации внутри одного SVG WebKit перерисовывает
   на каждом кадре; HTML-блоки двигает видеокарта, ~0%.
2. **Ходьба** (`go` в engine.ts) рассчитывается заранее и отдаётся браузеру как Web Animations: разгон, один шаг
   по кругу (iterations) и торможение. Ключевые кадры только в точках шага, между ними синусная кривая.
   Сотни keyframes WebKit гоняет на главном потоке — нельзя.
3. **«Кипящие» чернила** = 3 готовые копии рисунка с чуть сдвинутыми точками, которые сменяются CSS-анимацией
   прозрачности (0 скрипта). `ink: true` / `"lines"` — это; `"filter"` — старый шумовой фильтр (дорогой, только по просьбе).
4. **Моргание** — одна длинная CSS-петля на 13 с с несколькими морганиями (а не таймер в JS).
5. **`animation-direction: alternate-reverse` нельзя**: WebKit не отдаёт её видеокарте. Вместо неё — `alternate`
   с отрицательной задержкой в один круг. И у всех keyframes одной анимации должен быть одинаковый список функций
   transform (например, везде `translateY(..) rotate(..)`, а не `none` в одном кадре).
6. **Ничего не удалять со страницы**: удаление слоя заставляет WebKit держать картинку всей страницы (~55 МБ на
   полноэкранном оверлее). Пыль, вспышки, мячик, самолётик и облачко с репликой создаются один раз и потом
   только прячутся/показываются (`pooled()` в engine.ts). У всех эффектов `will-change`.
7. **Облачко с репликой** не следует за ним скриптом: ему дают те же анимации перемещения, что и Акко (`carry`).
8. **Глаза** смотрят на курсор по таймеру (часто, когда курсор рядом и двигается, редко — когда далеко или стоит),
   плавность даёт CSS-transition. Никаких requestAnimationFrame-циклов, пока его не тащат.
9. **След джетпака** — CSS-выхлоп внутри Акко (`.rb-exhaust`), а не искры из скрипта (было 23%, стало 8%).
10. **WebKit-флаги в main.swift:** `AcceleratedDrawingEnabled = false` (иначе любая перерисовка SVG держит
    ~110 МБ GPU-буферов) и `PreferPageRenderingUpdatesNear60FPSEnabled = true`.
11. **FrameCap.swift**: каждой CAAnimation, которую WebKit добавляет в этом процессе, ставится
    `preferredFrameRateRange` (60, при экономии 30). Иначе WindowServer рисует экран на 120 Гц.
12. Запись в localStorage («какие трюки он уже делал») — раз в 30 с и при остановке, а не после каждого трюка.

Мерить: `top -pid` по процессам «Akko», `com.apple.WebKit.GPU` и `com.apple.WebKit.WebContent`
(и `WindowServer` — приложение выключено / включено); память — `footprint <pid>` (строка «graphics» — картинки слоёв).
Запускай с `CHELIK_NO_CURSOR=1`, чтобы мышь не влияла на цифры. Проверять одно действие удобно так:
`CHELIK_EVAL='desk.chelik.pause(); …'` и дальше вручную ставить позу/анимацию.

## Отладка

- `CHELIK_EVAL="js"` — выполнить JS в странице после загрузки; доступны `desk.chelik` (экземпляр библиотеки) и `desk.play("jetpack")`.
- `CHELIK_WK_OFF="Флаг1,Флаг2"` — выключить WebKit-флаги для экспериментов.
- `CHELIK_NO_CURSOR=1` — не передавать курсор (для замеров).
- `CHELIK_FPS=n` — потолок кадров анимаций (0 — без потолка, т.е. 120 на ProMotion).
- `CHELIK_FRAME="x,y,w,h"` — поставить окно в заданный прямоугольник.
- `CHELIK_SNAP=/папка` — страница может попросить снимок себя: `window.webkit.messageHandlers.desk.postMessage({t:"snap", n:"имя", r:[x,y,w,h]})`
  → `/папка/имя.png`. Так можно посмотреть на Акко без доступа к записи экрана.
- Логи: запусти `"/Applications/Akko.app/Contents/MacOS/Akko"` из терминала. В stderr идут строки
  `chelik act: …`, `chelik autohide: …`, `chelik js: …` (ошибки JS тоже). В системном логе их не видно.
- В библиотеке `chelik.play()` возвращает список трюков, `chelik.play("имя")` запускает трюк сразу.

## Исправленные баги (чтобы не вернуть)

- **Зависание с крутящимся курсором** (ноябрь 2026): главный поток застревал в `CA::Context::commit_transaction`,
  а фоновый поток SkyLight одновременно уничтожал окно (`-[CAContext dealloc]`), взаимная блокировка внутри
  системы. Причина — `FrameCap` правил *все* анимации приложения (окно настроек, меню, всплывающие подсказки),
  да ещё и сам объект анимации на месте. Теперь он трогает только слои внутри веб-вида Акко
  (`FrameCap.root`) и меняет копию. Подсказки `.help` из настроек убраны. Хук `CHELIK_CAPLOG=1` пишет в лог,
  сколько анимаций ограничено.

- На десктопе `targets: ""` → `querySelectorAll("")` бросал ошибку, и Акко просто стоял.
  Теперь пустой селектор = нет целей, а после ошибки движок ждёт 1 с и не крутится вхолостую.
- Brave отпускает и снова берёт запрос «не гасить экран» → Акко мелькал. Отсюда задержка 6 с перед возвращением.
- После оптимизации: облачко с репликой и эффекты больше не удаляются, а прячутся. Если вернуть `el.remove()` —
  вернётся +55 МБ памяти.

## Что не сделано / идеи

- Иконки рабочего стола (через «Универсальный доступ») написаны, но не проверены вживую: у сборки не было доступа.
  После подписи ad-hoc каждая новая сборка теряет выданный доступ — его надо выдавать заново.
- Ширина Dock без доступа — прикидка (свёрнутые окна не учитываются, док выходит чуть уже настоящего).
- На окна он попадает только сам; брошенный мышью, на окно не приземляется (только на пол и на Dock).

- **Windows**: собрать (`npm run dist:win`) и проверить на Windows-машине. Проверить прохождение кликов насквозь
  и захват мышью, перенести туда автопрятки и окно настроек (сейчас там только меню в трее).
- Подпись кода: сборки не подписаны (на macOS при первом запуске — «Открыть» через правый клик).
  Для раздачи людям нужен Apple Developer ID и нотаризация.
- Библиотека не опубликована в npm (`core/package.json` готов, имя `akko`).
- Можно ещё снизить нагрузку: 30 кадров и в обычном режиме (WindowServer −5% ядра, но движение чуть менее плавное).
- Оставшиеся частые изменения из скрипта: смена позы и взгляд (~2–4 мс каждое). Ещё дешевле — только если делать
  позы целиком CSS-анимациями без смены класса.
- Отладочные логи (`NSLog`, `post({t:"log"})`) и хуки `CHELIK_*` оставлены намеренно, они дешёвые.
